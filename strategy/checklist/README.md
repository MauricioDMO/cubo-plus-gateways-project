## Plan de ejecución propuesto

Planificación desde el 14 de octubre; no se presupone trabajo realizado antes de esta fecha.

### 14–18 de octubre — Validar y decidir

- [ ] Confirmar roles, registro, fecha/hora de entrega y logística con el programa.
- [ ] Obtener URL y permisos de auditoría/staging; recopilar datos aprobados del negocio.
- [ ] Crear Google Doc y comprobar acceso/historial con el revisor.
- [ ] Completar auditorías, entrevistas exploratorias y comparación de competencia.
- [ ] Acordar arquitectura, alcance y criterios de aceptación con negocio/mentora.

### 19–25 de octubre — Construir el recorrido

- [ ] Ejecutar prototipo estratégico y validar flujos con usuarios.
- [ ] Conectar concierge a IA y generar itinerarios visuales.
- [ ] Implementar solicitud de reserva e integración de disponibilidad si es viable.
- [ ] Probar Bitcoin sandbox, referido/lealtad y eventos de atribución.
- [ ] Mantener evidencia diaria en GitHub y Google Docs.

### 26 de octubre–1 de noviembre — Verificar

- [ ] Ejecutar pruebas integrales, de errores, pagos y duplicados.
- [ ] Revisar móvil, escritorio, teclado, SEO y protección de datos.
- [ ] Documentar resultados, costos, APIs, limitaciones y recomendación final.
- [ ] Revisar manual técnico y manual de operación con todo el equipo.

### 2–3 de noviembre — Entregar

- [ ] Cerrar pendientes del [checklist de entregables](entregables.md) con evidencias.
- [ ] Generar y revisar PDF estratégico y `.txt` con URL pública del repositorio.
- [ ] Verificar permisos de documentos, prototipos y repositorio desde otra cuenta.
- [ ] Subir la carpeta de entrega al destino oficial y conservar comprobante.

### Antes del 8 de noviembre — Ensayar demo

- [ ] Ensayar diez minutos con los cuatro integrantes y arranque desde terminal.
- [ ] Mostrar el recorrido completo y distinguir sandbox, mocks y resultados reales.
- [ ] Preparar alternativa ante fallos de red/IA sin hacerla pasar por ejecución en vivo.
